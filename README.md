# Toastmasters Speech Evaluator

כלי הערכה אוטומטי לנאומים ול-Table Topics במועדון Toastmasters: מאזין לפגישת Zoom מהמחשב שלכם (בלי חיבור ל-API של Zoom), סופר מילות-מילוי (Filler Words, כמו תפקיד ה-Ah-Counter), נותן ציון ומשוב בנוסח Toastmasters, שולח לכל משתתף את המשוב שלו במייל, ושומר הכל כדי לעקוב אחרי מגמת שיפור לאורך זמן.

## איך זה עובד בפועל

**אין חיבור ל-API של Zoom, אין אפליקציית Zoom marketplace, אין עלות של Zoom, ואין צורך בטרמינל בכלל.** האזנה קורית ישירות בתוך הדשבורד בדפדפן: פותחים פגישה, לוחצים "Start Listening", והדפדפן מבקש הרשאה לשתף מסך + שמע (checkbox "Share audio"/"Share system audio") — זו הדרך שבה הדשבורד "שומע" את פגישת הזום, בלי להתקין שום דבר נוסף. הוא מזהה לבד מתי מישהו מתחיל/מפסיק לדבר, ומעלה כל "תור דיבור" לשרת. שם זה מתומלל מקומית וחינמית (רק כדי לספור מילות-מילוי ולמדוד קצב/משך — התמליל המלא לא במרכז, ואפשר לפתוח אותו רק אם רוצים), מקבל ציון, ונשמר.

**חשוב להבין מגבלה אחת:** האזנה ל"מה שיוצא מהרמקולים" (בין אם דרך הדפדפן ובין אם דרך הסקריפט המתקדם) תופסת את כל שאר המשתתפים, אבל **לא** את המיקרופון של המחשב שמריץ את הכלי (זום לא מנגן לך את הקול של עצמך חזרה). לכן מומלץ להריץ את הכלי ממחשב שמצטרף לפגישה בתור משתתף נוסף שקט (מיקרופון כבוי, מצלמה כבויה) — למשל מחשב של תפקיד הטיימר, ולא מהמחשב של אחד הדוברים בפועל.

**דרישת דפדפן:** Chrome או Edge בווינדוס/לינוקס עובדים מהקופסה. ב-macOS ובחלק מהדפדפנים שיתוף שמע-מערכת עלול לא להיות זמין — במקרה כזה יש חלופה מבוססת-סקריפט (ראו "שיטה מתקדמת" בסוף המסמך).

## זיהוי מי מדבר

יש שתי דרכים, וכדאי להשתמש בשתיהן יחד:

1. **ידני (מומלץ, הכי אמין):** בדשבורד, בכרטיסיית "Meeting Sessions", יש שדה "Now speaking" — לפני שקוראים למישהו לדבר (Table Topic הבא, או נאום), בוחרים את שמו מהרשימה ולוחצים "Set". כל תור דיבור הבא ישויך אליו אוטומטית, עד שמחליפים.
2. **אוטומטי (גיבוי):** אם לא הוגדר אף אחד, המערכת מנסה לזהות שם מתוך התמליל עצמו (למשל "Hi, my name is Dana" או "let's hear from David"), עם התאמה מטושטשת (fuzzy) מול רשימת המשתתפים.

## התקנה והרצה (חד-פעמי, ואז פקודה אחת בכל פגישה)

### שלב 1: הקמה חד-פעמית
```bash
cd backend
pip install -r requirements.txt
```

### שלב 2: בכל פגישה
```bash
cd backend
uvicorn app.main:app --host 0.0.0.0 --port 8000
```
פותחים דפדפן ל-`http://localhost:8000` (או לכתובת IP של המחשב אם הדשבורד רץ במחשב אחר), מוסיפים משתתפים (חד-פעמי, נשארים לצמיתות), יוצרים פגישה חדשה, ולוחצים "Start Listening". כשמופיע דיאלוג השיתוף של הדפדפן, בוחרים "Entire Screen" ומוודאים שה-checkbox "Share audio" (או "Share system audio") מסומן — זהו, כל תור דיבור מופיע בדשבורד תוך שניות.

## שליחת משוב במייל (חינמי)

לכל משתתף בדשבורד יש שדה email (ממולא בטאב Participants). כשיש הערכה מוכנה, מופיע כפתור "Send to participant" ליד השורה שלו — לוחצים, והוא מקבל **רק את ההערכה שלו**, לא לכולם.

הגדרה חד-פעמית (חינמי לגמרי דרך Gmail):
1. מפעילים אימות דו-שלבי (2-Step Verification) בחשבון ה-Gmail ששולח את המיילים.
2. יוצרים "App Password" בכתובת myaccount.google.com/apppasswords (חינמי, קוד בן 16 תווים).
3. מגדירים משתני סביבה לפני הרצת השרת:
```bash
export SMTP_HOST=smtp.gmail.com
export SMTP_PORT=587
export SMTP_USER=your_address@gmail.com
export SMTP_PASS=xxxxxxxxxxxxxxxx   # ה-App Password
export SMTP_FROM_NAME="Toastmasters Club Evaluator"
uvicorn app.main:app --host 0.0.0.0 --port 8000
```
כל ספק SMTP אחר (Outlook, Google Workspace של המועדון וכו') עובד באותו אופן — רק משנים HOST/PORT.

## מה נבדק בפועל

- `pytest tests/test_scoring.py` — 4 בדיקות יחידה על מנוע הניקוד עברו בהצלחה, כולל אחרי כל שינוי.
- הרצתי שרת אמיתי ובדקתי קצה-לקצה כמה פעמים: יצירת משתתף → פגישה → הגדרת "Now speaking" → שליחת תמליל בלי שום שם בתוכו → המערכת שייכה נכון למשתתף שנבחר ידנית, חישבה ציון, ושמרה.
- בדקתי זיהוי שם מתוך התמליל (ללא הגדרה ידנית): "Hi, my name is Dana" זוהה נכון מול "Dana Cohen" ברשימה (fuzzy matching).
- בדקתי את פרמטר `duration_seconds` (מה שהדפדפן שולח, בניגוד ל-WAV מהמאזין המקומי) — ה-API משתמש נכון בערך שנשלח במקום לחשב מה-קובץ.
- **התקנתי בפועל faster-whisper והרצתי תמלול אמיתי** דרך ה-API (לא רק לוגיקה מדומה) — עבד. הורדת המודל מ-Hugging Face נכשלה בסביבת הבדיקה שלי בגלל חסימת רשת בסביבה הזו (לא קשור לקוד) — בפועל, אצלכם זה יעבוד כרגיל כל עוד יש אינטרנט רגיל (ההורדה קורית פעם אחת, בפעם הראשונה שמריצים, ואז נשמרת מקומית).
- בדקתי סינטקטית את קוד ה-JavaScript של כפתור ההאזנה (`node --check`) — תקין. **לא בדקתי בפועל בדפדפן אמיתי** (אין לי דפדפן/מיקרופון בסביבה שלי) — זו הבדיקה הכי חשובה שנשארה לכם לעשות.
- בדקתי שליחת מייל ללא הגדרת SMTP — מחזיר שגיאה ברורה ("SMTP not configured") במקום קריסה; לא נבדקה שליחה אמיתית (דורש חשבון Gmail אמיתי + App Password משלכם).

## עלויות

- **תמלול, ניקוד, זיהוי דובר, שליחת מייל — הכל חינמי וכל התהליך רץ מקומית**, אין תשלום לפי שימוש.

## פריסה לענן — לינק אמיתי שכולם יכולים לפתוח (חינמי)

הכנתי את כל מה שצריך מבחינת קוד (`render.yaml`, `.gitignore`, תמיכה ב-Postgres דרך `TM_DATABASE_URL`). **חשוב לדעת:** שלושת השירותים למטה (GitHub, Neon, Render) הם חשבונות אישיים שלכם — יצירת חשבון דורשת אימות במייל שלכם, ואני לא יכול/אמור ליצור אותם במקומכם (זו לא בעיה טכנית, זו שאלה של זהות ובעלות על החשבון). אחרי שהם קיימים, כל השאר הוא פשוט להעתיק-הדביק.

### שלב 1: להעלות את הקוד ל-GitHub (חד-פעמי)
אם אין לכם חשבון, נרשמים בחינם ב-github.com. ואז יוצרים repository חדש וריק (בלי README, בלי gitignore — יש לנו כבר) בשם למשל `toastmasters-evaluator`. בטרמינל, בתוך תיקיית הפרויקט:
```bash
cd "C:\Users\HP\OneDrive\שולחן העבודה\toastmasters-evaluator"
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/<שם-המשתמש-שלכם>/toastmasters-evaluator.git
git push -u origin main
```
(אם `git` לא מזוהה כפקודה — מתקינים מ-git-scm.com קודם).

### שלב 2: מסד נתונים חינמי וקבוע (Neon)
נרשמים בחינם ב-neon.tech (בלי כרטיס אשראי), יוצרים פרויקט חדש, ומעתיקים את ה-"Connection string" שמוצג (נראה כמו `postgresql://user:pass@ep-xxxx.neon.tech/dbname`). שומרים אותו בצד — צריך אותו בשלב הבא.

### שלב 3: פריסה ב-Render
נרשמים בחינם ב-render.com (אפשר עם חשבון ה-GitHub). לוחצים **New → Blueprint**, בוחרים את ה-repository ש-push-תם בשלב 1 — Render יזהה אוטומטית את `render.yaml` ויציע להקים שירות בשם `toastmasters-evaluator`. לפני "Apply", בעורך משתני הסביבה ממלאים:
- `TM_DATABASE_URL` = ה-connection string מ-Neon (שלב 2)
- `SMTP_USER`, `SMTP_PASS`, `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587` — אם רוצים שליחת מייל (ראו "שליחת משוב במייל" למעלה)

לוחצים Apply. הבנייה הראשונה לוקחת כמה דקות (מוריד את כל התלויות כולל faster-whisper). בסיום, Render נותן לינק קבוע כמו `https://toastmasters-evaluator.onrender.com` — זה הלינק לשתף עם כולם.

**הערה:** ה-free tier של Render "נרדם" אחרי 15 דקות בלי שימוש, וההפעלה הבאה לוקחת כדקה (cold start) — לגמרי בסדר לשימוש של מועדון (לא רץ באמצע היום ריק), פשוט הכניסה הראשונה בכל פגישה תהיה קצת איטית.

## שיטה מתקדמת/חלופית: סקריפט מאזין נפרד (אופציונלי)

אם הדפדפן שלכם לא תומך בשיתוף שמע-מערכת (בעיקר macOS, או דפדפנים שאינם Chrome/Edge), יש חלופה: `listener/listen_and_score.py` — סקריפט Python שרץ בטרמינל ומקשיב ישירות לכרטיס הקול, בלי תלות בדפדפן.
```bash
cd listener
pip install -r requirements-listener.txt
python listen_and_score.py --api http://localhost:8000
```
ב-macOS צריך גם device וירטואלי חינמי כמו [BlackHole](https://github.com/ExistentialAudio/BlackHole) כדי לתפוס שמע-מערכת (ואז `--device "BlackHole 2ch"`). ב-Windows/לינוקס זה עובד ישירות. **הערה:** בגרסת NumPy חדשה יש אי-התאמה עם הספרייה `soundcard` שגורמת לקריסה (`fromstring is removed`) — זה כבר מתוקן בקובץ הנוכחי (יש shim בראש הקובץ), אין צורך לעשות כלום נוסף.

## הרחבה עתידית: Zoom RTMS (אופציונלי, לא נדרש)

בתיקייה `backend/app/services/zoom_rtms.py` ו-`backend/app/routers/zoom_webhook.py` יש שכבת אינטגרציה חלופית לחיבור ישיר ל-Zoom דרך ה-API הרשמי שלהם (RTMS — Realtime Media Streams). זו לא הדרך שבחרתם (דורשת אפליקציית Zoom Marketplace וקרדיטים בתשלום מ-Zoom), אבל היא שמורה בקוד למקרה שתרצו בעתיד חיבור "רשמי" יותר. אפשר להתעלם ממנה לגמרי.

## מגבלות ידועות

- **זיהוי דובר** מסתמך על הגדרה ידנית ("Now speaking") או על שם שנאמר בתמליל. בלי אחד מהשניים, התור נשמר בלי שיוך למשתתף (עדיין מקבל ציון ומילות-מילוי, רק לא מקושר לאדם ספציפי).
- **מילות מילוי** מוגדרות לאנגלית בלבד. קל להוסיף רשימה בעברית ב-`filler_words.py` אם תרצו.
- **המחשב/הדפדפן המאזין לא שומע את עצמו** — ראו הסבר למעלה, ומכאן ההמלצה להריץ אותו ממחשב "שקט" בפגישה.
- **וריאציה קולית** (vocal variety) לא נמדדת — דורשת ניתוח אודיו מעבר לתמליל בלבד.
- כפתור "Start Listening" דורש שהכרטיסייה תישאר פתוחה בדפדפן לאורך כל הפגישה (אם סוגרים את הכרטיסייה, ההאזנה נעצרת).
